# Java & Spring Boot 코드 컨벤션 프롬프트

다음 코드 컨벤션과 클린 코드 원칙을 따르는 [요청한 기능]에 대한 코드를 작성해 주세요. 각 코드 조각에 대해 **왜** 그리고 **어떻게** 이런 방식으로 구현했는지 설명해 주세요.

## 1. SOLID 원칙

- **단일 책임 원칙(SRP)**: 각 클래스는 단 하나의 책임만 가져야 합니다.
- **개방-폐쇄 원칙(OCP)**: 클래스는 확장에는 열려 있고, 수정에는 닫혀 있어야 합니다.
- **리스코프 치환 원칙(LSP)**: 하위 클래스는 상위 클래스를 대체할 수 있어야 합니다.
- **인터페이스 분리 원칙(ISP)**: 클라이언트는 사용하지 않는 인터페이스에 의존해서는 안 됩니다.
- **의존성 역전 원칙(DIP)**: 고수준 모듈은 저수준 모듈에 의존해서는 안 됩니다. 둘 다 추상화에 의존해야 합니다.

## 2. 코드 구조 원칙

- **들여쓰기 제한**: 한 메서드에 오직 한 단계의 들여쓰기만 사용하세요.
- **else 예약어 사용 지양**: 조건문 중첩을 줄이고 early return 패턴을 사용하세요.
- **원시값과 문자열 포장**: 의미 있는 클래스로 원시 타입을 감싸세요.
- **일급 컬렉션 적용**: 컬렉션을 포함한 전용 클래스를 생성하여 관련 동작과 검증을 캡슐화하세요.
- **인스턴스 변수 최소화**: 클래스의 인스턴스 변수는 3개 이하로 유지하세요.
- **getter/setter 지양**: 도메인 객체에서는 행동 중심 메서드를 사용하세요(DTO 제외).

## 3. 메서드 설계

- **인자 수 제한**: 메서드 인자는 3개 이하(가능하면 2개 이하)로 유지하세요.
- **점(.) 표기 최소화**: 메서드 체이닝을 지양하고 디미터의 법칙을 준수하세요.
- **단일 책임 원칙 적용**: 메서드는 한 가지 일만 수행해야 합니다.
- **명명 규칙**: 메서드 이름은 수행하는 작업을 명확히 나타내야 합니다.
- **메서드 길이 제한**: 메서드는 10-15줄 이내로 유지하세요.

## 4. 클래스 설계

- **작은 클래스 유지**: 큰 클래스는 더 작은 클래스들로 분리하세요.
- **클래스 간 명확한 책임 분리**: 각 클래스는 명확한 도메인 개념이나 기능을 표현해야 합니다.
- **상속보다 구성 사용**: 상속 대신 구성(Composition)을 통해 기능을 확장하세요.
- **추상화 적절히 사용**: 인터페이스나 추상 클래스를 통해 적절한 추상화 레벨을 유지하세요.

## 5. 예외 처리

- **예외 유형 구분**: 검사 예외와 비검사 예외를 적절히 구분하여 사용하세요.
- **사용자 정의 예외 사용**: 도메인 특화 예외를 사용하여 예외 처리 의도를 명확히 하세요.
- **예외 포장**: 저수준 예외는 상위 수준의 의미 있는 예외로 변환하세요.
- **try-catch 위치**: 예외 처리는 적절한 추상화 레벨에서 수행하세요.

## 6. 테스트 코드

- **테스트 단위 명확화**: 각 테스트는 명확한 단위(unit)와 목적을 가져야 합니다.
- **테스트 독립성**: 각 테스트는 다른 테스트에 의존해서는 안 됩니다.
- **테스트 명명 규칙**: `[테스트할_메서드]_[시나리오]_[예상결과]` 패턴 사용.
- **테스트 가독성**: Given-When-Then 또는 Arrange-Act-Assert 패턴을 사용하세요.
- **테스트 커버리지 최대화**: 핵심 비즈니스 로직에 대해 철저한 테스트를 작성하세요.

## 7. 레이어별 구현 지침

### 7.1 컨트롤러 레이어
- API 엔드포인트 정의 및 요청/응답 처리
- 입력 유효성 검사
- 서비스 레이어 호출 및 결과 반환
- 예외를 적절한 HTTP 응답으로 변환

### 7.2 서비스 레이어
- 트랜잭션 경계 설정
- 비즈니스 로직 구현
- 여러 리포지토리 조합
- 도메인 이벤트 발행

### 7.3 리포지토리 레이어
- 데이터 접근 로직 캡슐화
- 쿼리 최적화
- 엔티티 매핑 관리

### 7.4 엔티티/도메인 레이어
- 핵심 비즈니스 규칙 및 로직 포함
- 불변성 및 유효성 검사 보장
- 풍부한 도메인 모델 구현
- 적절한 연관관계 매핑
